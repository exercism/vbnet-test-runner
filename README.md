# Exercism Visual Basic Test Runner

The Docker image to automatically run tests on Visual Basic solutions submitted to [Exercism].

## Run the test runner

To run the tests of an arbitrary exercise, do the following:

1. Open a terminal in the project's root
2. Run `./bin/run.sh <exercise-slug> <solution-dir> <output-dir>`

Once the test runner has finished, its results will be written to `<output-dir>/results.json`.

## Run the test runner on an exercise using Docker

_This script is provided for testing purposes, as it mimics how test runners run in Exercism's production environment._

To run the tests of an arbitrary exercise using the Docker image, do the following:

1. Open a terminal in the project's root
2. Run `./bin/run-in-docker.sh <exercise-slug> <solution-dir> <output-dir>`

Once the test runner has finished, its results will be written to `<output-dir>/results.json`.

## Run the tests

To run the tests to verify the behavior of the test runner, do the following:

1. Open a terminal in the project's root
2. Run `./bin/run-tests.sh`

These are [golden tests][golden] that compare the `results.json` generated by running the current state of the code against the "known good" `tests/<test-name>/results.json`. All files created during the test run itself are discarded.

When you've made modifications to the code that will result in a new "golden" state, you'll need to generate and commit a new `tests/<test-name>/results.json` file.

## How the runner builds and runs a solution

The runner has two ways to build a solution and run its tests:

1. **The fast path** compiles the solution with Roslyn inside the runner's own process. It skips `dotnet restore` and MSBuild, which take most of the time in a normal run.
1. **MSBuild** restores and builds the project with `dotnet build`.

Both ways then run the xUnit v3 test executable directly. The runner uses MSBuild whenever the fast path can't handle the solution. To turn the fast path off, for example to compare its results with MSBuild's, set the environment variable `EXERCISM_FAST_PATH=off`.

### Project shapes

The fast path still compiles each solution with the settings from its own `.vbproj`. Exercises with identical project files (apart from their names) compile the same way, so the runner groups them into shapes. The `shapes/` folder holds one template project file for each shape found in the track's history since the switch to xUnit v3.

When the Docker image is built, `bin/build-shapes.sh` builds each template with the real .NET SDK. It keeps the exact compiler command line, the source files generated by the SDK and packages, and a folder with every dependency precompiled with ReadyToRun. At run time, the runner reduces the solution's `.vbproj` to a key (see `ProjectShape.vb`) and looks for a template with the same key. If it finds one, it compiles the solution's files with that template's compiler arguments and the solution's root namespace.

### When the fast path hands over to MSBuild

The runner prints `Fast path not used: <reason>` and uses MSBuild if any of these is true:

- No shape matches the project file. This happens if the project file has anything other than plain properties, `Import` items and `PackageReference` items, or if it has a combination of settings with no template.
- The solution folder has a `bin` or `obj` folder, another project file, a `Directory.Build.*` or `Directory.Packages.props` file, `global.json`, `nuget.config`, `AssemblyInfo.vb`, a `.resx`, `.myapp`, `.settings` or `.globalconfig` file, or an `.editorconfig` that changes diagnostics.
- A source file is not valid UTF-8, or uses something that needs a source generator or analyzer (such as `<GeneratedRegex>`), or has a `<Fact>` or `<Theory>` outside the test file.

### Adding a new shape

If the track changes an exercise's `.vbproj` (for example to bump a package version or add a package), solutions for that exercise will use MSBuild until the image has a matching shape. They will still pass or fail correctly, just more slowly. To add the new shape:

1. Make sure any new package is pre-installed in the `Dockerfile`, as before.
1. Regenerate the shapes from a checkout of the track repo, with `python3 bin/generate-shapes.py shapes <path to exercism/vbnet>`. You can also copy the new `.vbproj` into a new folder as `shapes/<n>/ExercismShape.vbproj` by hand.
1. Rebuild the image. The build log says `Built shape ...` for each shape, or `Skipping shape ...` if a template failed to build.
1. Run an exercise with the new project file, and check that the runner does not print `Fast path not used: unknown project shape`.
